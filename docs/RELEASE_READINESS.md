# جاهزية إصدار Project Desk

> آخر تحديث بنيوي: 26 أغسطس 2026  
> ملف النشر المستهدف: v1 داخلي، خادم Linux واحد، SQLite محلية بوضع WAL،
> وتخزين ملفات خاص.

## 1. قرار الإصدار

تستخدم هذه الوثيقة قرارين منفصلين لا يجوز دمجهما:

1. **اكتمال المستودع:** الوظائف والضوابط موجودة في الكود، مرتبطة بمتطلبات،
   ولها اختبارات آلية قابلة للتشغيل.
2. **تصريح الإنتاج:** بيئة النشر والتكاملات الخارجية وتمارين التعافي والوصولية
   والـpilot اجتازت أدلة تشغيل فعلية.

الوضع الحالي هو: **نطاق v1 منفذ في المستودع، وقد اجتاز بوابة المستودع الآلية
المحلية في 26 أغسطس 2026. الإنتاج غير مصرح به حتى يطابق `APP_RELEASE_SHA`
الـSHA النهائي داخل ملف الأدلة وتُغلق البنود الخارجية أدناه.**

وجود adapter للماسح أو اختبار استعادة آلي أو ملف رحلة متصفح لا يثبت وحده أن
الماسح الحقيقي أو الوجهة الخارجية أو البيئة الإنتاجية قد اختُبرت.

## 2. هوية مرشح الإصدار

يملأ مسؤول الإصدار هذه الحقول من التشغيل نفسه، لا من تشغيل سابق:

| الحقل | القيمة |
|---|---|
| Git commit SHA | لا يُثبت رقم قابل للتقادم هنا؛ المصدر الملزم هو `APP_RELEASE_SHA` المطابق لـ`release_sha` في ملف أدلة الإنتاج |
| تاريخ ووقت التحقق والمنطقة الزمنية | `2026-08-26 Africa/Tripoli (UTC+02:00)`؛ يضيف مسؤول الإصدار الوقت الدقيق داخل دليل التشغيل النهائي |
| نظام التشغيل وإصدارات PHP/Node/pnpm | Windows 11 `10.0.22631`؛ PHP `8.5.8`؛ Composer `2.10.2`؛ Node `24.19.0`؛ pnpm `11.19.0` محلياً (`11.16.0` في CI) |
| قاعدة الاختبار وحالة migrations | SQLite محلية؛ جميع migrations حتى `2026_08_12_000430` مطبقة |
| مسؤول التحقق | Codex — تحقق آلي محلي على بيئة التطوير |
| مكان سجل الأوامر ولقطات المتصفح | `storage/app/browser-tests/`؛ وملخص الأوامر في هذه الوثيقة |

أي تعديل بعد تسجيل SHA يبطل النتيجة إلى أن تعاد البوابة على SHA الجديد.

تشغّل الأوامر من جذر المشروع على تثبيت نظيف قدر الإمكان. لا تُملأ خانة النتيجة
إلا بناتج التشغيل الكامل.

| البوابة | الأمر المرجعي | معيار النجاح | النتيجة الحالية |
|---|---|---|---|
| سلامة Composer | `composer validate --strict --no-check-publish` | خروج 0 دون خطأ تحقق | ناجح؛ `composer.json is valid` |
| الثغرات المعروفة في القفل | `composer audit --locked --no-interaction` | لا advisory مانعة | ناجح؛ لا advisories معروفة |
| PHP style/static/tests | `composer test` | Pint وPHPStan والاختبارات تخرج 0 | ناجح؛ Pint وPHPStan وPHPUnit خرجت 0 |
| تنسيق الواجهة | `pnpm run format:check` | خروج 0 | ناجح على Node 24 |
| ESLint | `pnpm run lint:check` | خروج 0 | ناجح على Node 24 |
| TypeScript | `pnpm run types:check` | خروج 0 | ناجح على Node 24 |
| بناء الإنتاج | `pnpm run build` | خروج 0 وassets قابلة للتحميل | ناجح؛ Vite `8.2.1` |
| migrations | `php artisan migrate:status` | كل migrations المطلوبة مطبقة | ناجح على قاعدة الاختبار المعزولة؛ 20 migration |

| فحص جاهزية الإنتاج | `php artisan project-desk:production-readiness` | خروج 0 وتطابق SHA والأدلة الخارجية | يفشل مغلقًا محليًا كما هو متوقع؛ لا يصبح ناجحًا قبل تجهيز الخادم والأدلة |

تشمل مجموعة المتصفح التي يستدعيها `tests/Browser/run-all.mjs`:

- رحلة عميل ثم جهة اتصال أساسية ثم مشروع بلا مهام ثم «إضافة أول مهمة»؛
- المسارات العامة وقوالب الفواتير والملفات ومركز البيانات والإعدادات؛
- الحوكمة والاجتماعات والتنبيهات وتفضيلاتها؛
- الاستجابة والوصولية الآلية وتراجعات قائمة/كانبان المهام؛
- حراسة المسودات غير المحفوظة عند Escape والنقر الخارجي والإغلاق والتنقل وزر
  الرجوع، مع إعادة التركيز بعد القرار.

## 4. قدرات المستودع التي تعتمد عليها الجاهزية

- لوحة المتابعة والجدول الأسبوعي وقائمة المشاريع تستمد التقدم والصحة والمرحلة
  التالية من خدمات حساب مشتركة، مع drill-down يفسر المؤشرات.
- رفع الملف ينشئ `file_objects` خاصاً ورابط هدف إلى المشروع أو مهمة أو متطلب
  نشطين من المشروع نفسه. التحقق من الهدف والصلاحية يجري قبل التخزين وداخل
  المعاملة، والتنزيل متاح لحالة `safe` فقط.
- عقد `MalwareScanner` يدعم command أو callback. تعطل الماسح أو غياب تكامل
  صالح في الإنتاج يغلق الرفع/التنزيل بدلاً من اعتبار التحقق البنيوي فحصاً آمناً.
- أمر الاحتفاظ يراجع الملفات اليتيمة بعد مهلة، ويحمي الروابط المؤرشفة وكراسات
  المتطلبات والمحاضر وملفات مركز البيانات والنسخ، ويستخدم lock وسياج الاستعادة
  وحجراً قابلاً للتراجع. يبدأ أول تشغيل إنتاجي بـ`--dry-run`.
- حزمة `.pdesk` مشفرة ومصادق عليها، وتتحقق من لقطة SQLite ومن مخزون الملفات
  وchecksums. الاستعادة تتحقق قبل الاستبدال، تنشئ safety backup، وتعزل WAL/SHM،
  وتحمي الكتابات المتزامنة بسياج؛ الحزم القديمة database-only لا تعيد ملفات
  لم تكن داخلها.
- `lock_version` يمنع overwrite صامتاً في المشاريع والمهام والمتطلبات وقوالب الفواتير
  والمخاطر والمشكلات والمراحل والاجتماعات والمحاضر. سجل النشاط يكتب داخل معاملة
  المجال نفسها؛ لا يصبح مرئياً إلا عند commit ويلغى مع rollback، وهو اتساق ذري
  مناسب لملف v1 أحادي قاعدة البيانات.

التفاصيل واختبارات كل قدرة في
[مصفوفة تتبع المتطلبات](REQUIREMENTS_TRACEABILITY.md).

## 5. بوابات الإنتاج الخارجية

### 5.1 ماسح برمجيات خبيثة فعلي

- [ ] ضبط `MALWARE_SCANNER_DRIVER=command` مع executable موثوق أو `callback`
  مع تنفيذ فعلي للعقد، وعدم استخدام null/fake scanner في الإنتاج.
- [ ] إثبات رفع ملف نظيف معتمد وانتقاله إلى `safe` ثم تنزيله بصلاحية صحيحة.
- [ ] إثبات اكتشاف عينة اختبار قياسية معتمدة داخل بيئة معزولة، وحجرها ومنع
  تنزيلها، دون استخدام ملف ضار حقيقي.
- [ ] إيقاف الماسح مؤقتاً وإثبات fail-closed وظهور حدث قابل للمراقبة.
- [ ] توثيق تحديث توقيعات الماسح ومراقبة فشل الخدمة ومسؤول الاستجابة.

**الدليل المطلوب:** إعدادات منقحة بلا أسرار، سجل التشغيل، معرفات audit، واسم
المسؤول والتاريخ.

### 5.2 نسخة خارج المضيف وتمرين استعادة

- [ ] حفظ `BACKUP_ENCRYPTION_KEY` في مدير أسرار منفصل عن الحزم والمضيف.
- [ ] نسخ حزمة `.pdesk` مكتملة إلى تخزين مشفر off-host أو immutable والتحقق من
  SHA-256 بعد النقل.
- [ ] إجراء restore drill شهري على نسخة معزولة بعد إيقاف أي writers مخصصة.
- [ ] التحقق بعد الاستعادة من الدخول، وعدد ممثل من المشاريع والمهام، وكراسات
  المتطلبات، والمحاضر، وتنزيل عدة مرفقات، لا مجرد فتح الحزمة.
- [ ] قياس وإثبات `RPO ≤ 24h` و`RTO ≤ 4h` أو تسجيل استثناء معتمد قبل الإطلاق.
- [ ] اختبار دوران مفتاح النسخ مع بقاء المفاتيح السابقة حتى انتهاء حزمها.

**الدليل المطلوب:** معرف الحزمة وchecksum الخارجي، وقت البداية والنهاية، نتيجة
فحوص التطبيق، ومكان off-host منقح دون كشف أسرار.

### 5.3 TLS والجلسات والعمليات الخلفية

- [ ] `APP_ENV=production` و`APP_DEBUG=false`، وأسرار البيئة خارج Git.
- [ ] HTTPS فقط بشهادة سليمة وتحويل HTTP، مع `SESSION_ENCRYPT=true` و
  `SESSION_SECURE_COOKIE=true` وفحص خصائص Cookie في المتصفح.
- [ ] scheduler يعمل كل دقيقة وتوجد مراقبة لآخر نجاح للتنبيهات والنسخ وتنظيف
  الملفات اليتيمة.
- [ ] queue worker تحت systemd/Supervisor مع restart ومراقبة الفشل.
- [ ] SQLite على تخزين محلي durable لا NFS/SMB، مع WAL ومساحة ومراقبة ونسخ
  خارج مجال الفشل نفسه.
- [ ] فحص سجلات التطبيق والـproxy ومنع الأسرار والبيانات الحساسة فيها، وضبط
  تدوير السجلات والتنبيه.

**الدليل المطلوب:** نتائج فحص TLS/Cookie، حالة الخدمات، لقطة `schedule:list`،
وسجل نجاح دورة مجدولة فعلية.

### 5.4 الوصولية اليدوية والتكبير

- [ ] تنفيذ الرحلات الحرجة بالكيبورد فقط، بما فيها الحوارات والكانبان والجداول.
- [ ] اختبار قارئ شاشة فعلي في مجموعة متصفح/قارئ معتمدة، مع أسماء controls
  العربية، وترتيب القراءة، ورسائل الأخطاء وتغيرات الحالة.
- [ ] اختبار تكبير 200% وعدم وجود فقد محتوى أو تمرير أفقي للصفحة؛ يستثنى scroller
  الجدول الأسبوعي المقصود.
- [ ] مراجعة RTL/Bidi للبريد والهاتف والكود والتاريخ، وfocus المرئي وreduced
  motion وعدم الاعتماد على اللون وحده.
- [ ] تسجيل العوائق الحرجة وإغلاقها أو اعتماد استثناء موثق قبل Go.

الفحص الآلي في المستودع يساعد في اكتشاف التراجعات، لكنه لا يثبت وحده WCAG 2.2
AA ولا يغني عن قارئ الشاشة والتكبير اليدويين.

### 5.5 الأداء وتجربة الـpilot

- [ ] قياس Web Vitals على بيئة قريبة من الإنتاج وببيانات ممثلة، وتحقيق
  `p75 INP ≤ 200ms` للعمليات المعتادة.
- [ ] إثبات `search p95 ≤ 500ms` بالحجم المستهدف، مع توثيق الجهاز والبيانات.
- [ ] Pilot داخلي على مشروعين حقيقيين و8–12 مستخدماً مع بيانات منقحة وموافقة
  أصحابها.
- [ ] نجاح 90% على الأقل من السيناريوهات الحرجة دون مساعدة، و`SUS ≥ 75`.
- [ ] مراجعة الملاحظات ذات الشدة العالية وإغلاقها أو اعتماد قرار تأجيل صريح.

**الدليل المطلوب:** تقرير القياس، تعريف العينة والسيناريوهات، نتيجة SUS، وقائمة
القرارات دون إدراج بيانات شخصية غير لازمة.

## 6. قرار Go / No-Go والتراجع

لا يصدر قرار **Go** إلا بعد:

- نجاح بوابة المستودع على SHA نفسه؛
- إغلاق كل checkbox خارجي أو وجود استثناء مكتوب بمالك وتاريخ انتهاء؛
- وجود نسخة off-host مجربة وخطة تراجع ونافذة صيانة وجهة اتصال للحادث؛
- توقيع مسؤول المنتج ومسؤول التقنية ومسؤول التشغيل.

| الاعتماد | الاسم | القرار | التاريخ | رابط الدليل/الاستثناء |
|---|---|---|---|---|
| المنتج |  | Go / No-Go |  |  |
| التقنية |  | Go / No-Go |  |  |
| التشغيل/الأمن |  | Go / No-Go |  |  |

قبل النشر سجل الإصدار السابق القابل للاسترجاع، وخذ نسخة `.pdesk` مكتملة وانسخها
خارج المضيف، وحدد معيار التراجع ومالك القرار. عند فشل migration أو فحص الدخول أو
سلامة الملفات، أوقف الكتابة ولا تعاود الاستعادة عشوائياً؛ اتبع
[دليل النسخ والاستعادة](BACKUP_AND_RECOVERY.md) واحتفظ بحزم المصدر و`pre_restore`
وملفات العزل للتحليل.
