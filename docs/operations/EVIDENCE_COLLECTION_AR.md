# جمع أدلة جاهزية إنتاج Project Desk

هذا الملف يحدد ما يجب جمعه لملف `production-evidence.json` ذي schema v2. لا يمثل القالب دليلًا ولا يجوز تعبئة نتيجة لم تُشاهد فعليًا. احفظ الأدلة التفصيلية في مخزن وصول مقيد، وضع في JSON القيم المنقحة والمعرفات فقط.

## تثبيت الإصدار والبيئة

- جمّد SHA واحدًا من 40 خانة واضبطه في `APP_RELEASE_SHA` وفي رأس الملف وفي أقسام scanner وoffsite backup وrestore وaccessibility وperformance وpilot.
- سجل URL الإنتاج، معرف الخادم، Ubuntu وPHP ومسار SQLite المحلي.
- أنشئ الملف النهائي خلال 24 ساعة من قرار Go؛ أي تعديل على الكود يلغي الأدلة المرتبطة بالـSHA السابق.

## ClamAV

على staging معزول ارفع ملفًا نظيفًا، ثم EICAR من مصدر رسمي وقت الاختبار، ثم أوقف `clamd` واختبر ملفًا آخر. لكل حالة سجل:

- وقت الاختبار ومعرف activity/audit؛
- حالة الملف وعدم إمكان تنزيل infected أو failed؛
- إصدار ClamAV وعمر التوقيعات؛
- اسم المراجع ونتيجة pass/fail.

لا تحفظ EICAR في Git أو في حزمة النسخ. أعد تشغيل الخدمة بعد اختبار الانقطاع وتحقق من عودتها.

## النسخ الخارجي والاستعادة

احتفظ بنتيجة `offsite-backup-status.json` ونتيجة `verify-s3-object-lock.sh`. سجل bucket وobject key وVersion ID ووقت الإنشاء ووقت انتهاء retention وSHA-256 المحلي ونجاح `rclone check`. لا تسجل access keys.

في تمرين الاستعادة الشهري استخدم بيئة معزولة ومسار قاعدة مختلفًا مثبتًا مسبقًا. سجل البداية والنهاية وRPO وRTO وchecksum، ثم اختبر الدخول والمشاريع والمهام والكراسات والمحاضر والملفات. لا تنفذ الاستعادة على الإنتاج لجمع دليل.

## الوصولية اليدوية

ينفذ مراجع مسمى الرحلات الحرجة بالعربية والإنجليزية على Chrome وFirefox باستخدام الكيبورد فقط وNVDA. يسجل لكل رحلة pass/fail وملاحظة العائق، إضافة إلى Bidi والتكبير 200% وreduced motion. لا يعتمد القسم إلا عندما تكون الحقول الخمسة كلها true ولا توجد عوائق مانعة مفتوحة.

## الأداء

استخدم staging مطابقًا للإنتاج ببيانات منقحة تمثل 10,000 مهمة و1,000 متطلب وكراسة 300 صفحة و12 جلسة. سجل مواصفات الجهاز، المتصفح، الشبكة، تاريخ القياس، وحجم البيانات.

- INP: اجمع 200 interaction حقيقي على الأقل من الجلسات، واحسب p75 من القيم الخام.
- البحث: نفذ 100 قياس على الأقل تشمل warm وcold، وسجل العينات الخام واحسب p95.

لا تنقل percentile يدويًا دون حفظ ملف العينات الذي يسمح بإعادة الحساب.

## Pilot وSUS

يشمل Pilot مشروعين حقيقيين و8–12 مستخدمًا. لكل رحلة سجل الاسم وعدد المحاولات وعدد النجاحات دون مساعدة. يحسب النظام النسبة من الأعداد الخام ويرفض نسبة مجمعة غير مطابقة. يجمع SUS من كل مستخدم، وتدخل الدرجة النهائية بين 0 و100 وعدد الاستجابات.

## الاعتماد النهائي

بعد نجاح `composer ci:check` و`browser:release` ثلاث مرات وViewer audit وpreflight، يوقع مسؤول المنتج والتقنية والتشغيل بأسماء غير فارغة وتوقيت ISO-8601. ثم يشغل مسؤول الإصدار:

```bash
php artisan project-desk:production-readiness --json
```

الخروج `0` و`ready: true` هما المصدر الآلي النهائي. أي نقص أو دليل قديم أو SHA مختلف يعيد القرار إلى `No-Go`.
