# فهرس حزمة Project Desk Development v2

## 1. الغرض

هذه الحزمة مستقلة عن وثائق النسخة الأولى، وتصف تنفيذ فرع `develop` بتاريخ 23 أغسطس 2026. تحتفظ الوثائق الأساسية السابقة داخل المستودع للمرجعية، لكن ملفات `Project-Desk-Development-v2` هي مرجع الإضافات الجديدة.

## 2. المخرجات النهائية

| الملف | الجمهور | الغرض |
|---|---|---|
| SRS IEEE 830 | مالك المنتج، QA، التطوير | المتطلبات الوظيفية وغير الوظيفية وقواعد العمل والقبول والتتبع. |
| التوثيق التقني | المطور والتشغيل والأمن | المعمارية والبيانات والعقود والخوارزميات والتشغيل. |
| دليل المستخدم | Admin وPM والمستخدم | الاستخدام التفصيلي للميزات القديمة والجديدة. |
| دليل Workflows | الفريق والإدارة | طريقة العمل النموذجية والرسومات وتسلسل القرارات. |
| المقارنة التنافسية | الإدارة والمنتج | تحديث المزايا والعيوب والتموضع بعد v2. |
| تقرير التنفيذ والتحقق | QA وصاحب القرار | ما نُفذ، الأدلة، الاختبارات، وحدود الجاهزية. |
| تقرير جودة المستندات | QA وصاحب القرار | عدد الصفحات، فحص الإتاحة، سلامة التخطيط، والتحقق البصري. |

## 3. صيغ التسليم

- Markdown كمصدر نصي قابل للمراجعة في Git.
- DOCX للقراءة والتحرير والطباعة.
- PDF ثابت للمشاركة والأرشفة.
- PNG للمخططات المستقلة عالية الدقة.
- ZIP للحزمة الكاملة.
- `MANIFEST-SHA256.txt` للتحقق من سلامة الملفات.

## 4. ترتيب القراءة

### للإدارة

1. المقارنة التنافسية.
2. تقرير التنفيذ والتحقق.
3. تقرير جودة المستندات.
4. SRS: الملخص والنطاق والقبول.

### لمدير المشروع

1. دليل المستخدم.
2. Workflows.
3. SRS: قواعد المراحل والتحليل والمراجعة.

### للمطور والتشغيل

1. التوثيق التقني.
2. SRS والمصفوفة.
3. تقرير التنفيذ والتحقق.
4. `docs/LOCAL_REQUIREMENTS_ANALYSIS_AR.md`.

## 5. سياسة المرجعية

- الكود والاختبارات هما دليل التنفيذ.
- SRS هي مرجع المتطلبات والقبول.
- التوثيق التقني يشرح كيفية التنفيذ والتشغيل ولا يوسع النطاق.
- دليل المستخدم يشرح السلوك المتاح ولا يَعِد بميزات غير منفذة.
- المقارنة التنافسية تبقي حقائق المنافسين مؤرخة بمصادر الدراسة الأصلية.
