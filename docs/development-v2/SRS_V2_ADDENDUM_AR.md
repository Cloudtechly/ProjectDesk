# الملحق الحاكم لإصدار Project Desk Development v2

> حالة الوثيقة: منفذ ومتحقق في فرع `develop`  
> تاريخ خط الأساس: 23 أغسطس 2026  
> يدمج هذا الملحق داخل كراسة IEEE 830 الأصلية ويحل محل أي وصف سابق يتعارض معه.

## 1. نطاق الإصدار التطويري

يضيف الإصدار Development v2 أربع قدرات مترابطة دون تحويل النظام إلى نظام محاسبي أو منصة DevOps:

1. خطة مراحل موزونة وMilestones وبوابات اعتماد مرتبطة بالمهام والمتطلبات.
2. إدخال مشروع قائم بدأ قبل استخدام النظام مع Snapshot انتقال غير قابل للتعديل.
3. تصنيف المتطلبات داخل فئات ومجموعات وعلاقات ومصادر قابلة للتتبع.
4. تحليل محلي لكراسات PDF وDOCX بواسطة Ollama وQwen3 وOCR دون إرسال المحتوى إلى الإنترنت.

## 2. تعديلات الوصف العام

### 2.1 منظور المنتج

يبقى Project Desk تطبيق Laravel/Inertia/React أحادي المؤسسة، ويضاف إليه عامل Queue محلي للتعامل مع التحليل الثقيل. محرك اللغة عملية محلية منفصلة على `127.0.0.1:11434`، ولا يملك وصولاً إلى قاعدة البيانات أو الأدوات أو ملفات غير الإصدار المحدد.

### 2.2 فئات المستخدمين

- مدير النظام: يضبط المحرك المحلي، يختبر التبعيات، ويتجاوز تحذير Prompt Injection الحرج بعد مراجعة صريحة.
- مدير المشروع: ينشئ خطة المراحل، يدخل مشروعاً قائماً، يبدأ التحليل، ويراجع ويعتمد Candidates.
- Member وViewer: يطالعان المخرجات المصرح بها، ولا يعتمدان نتائج التحليل أو يغيران إعدادات المحرك.

### 2.3 بيئة التشغيل الإضافية

| المكون | الحد الأدنى/العقد |
|---|---|
| Ollama | Windows محلي، loopback فقط، المنفذ 11434 |
| النموذج | `qwen3:8b-q4_K_M`، سياق افتراضي 8192 |
| GPU المرجعي | NVIDIA RTX 4060 بذاكرة 8GB |
| الذاكرة | 16GB RAM |
| PDF النصي | Poppler: `pdfinfo`, `pdftotext`, `pdftoppm` |
| OCR | Tesseract مع `ara+eng` |
| الطابور | Database Queue، عملية `local-ai` واحدة |
| حدود الرفع | 25MB و300 صفحة افتراضياً |

## 8. حالات الحياة الجديدة

### 8.1 عملية التحليل

`queued -> waiting_for_engine/extracting -> security_review_required/analyzing -> merging -> review_ready -> approved`

المسارات النهائية البديلة: `failed` أو`cancelled`. يمكن إعادة عملية failed أو cancelled بإذن مناسب، بينما لا تعاد approved على البصمة نفسها بلا إصدار/تعليمات جديدة.

### 8.2 Candidate

`pending -> approved | rejected | merged | converted_to_question | converted_to_risk`

لا ينتقل Candidate النهائي تلقائياً إلى حالة أخرى، ويظل قرار المراجع وتوقيته محفوظين.
