# Project Desk

نظام إدارة مشاريع داخلي لـCloudTech، مبني بـLaravel وReact/Inertia، بواجهة
عربية افتراضية باتجاه RTL وواجهة إنجليزية باتجاه LTR. يجمع إدارة المشاريع
والمهام والعملاء والفريق والمتطلبات والاجتماعات والملفات وقوالب الفواتير ومركز
البيانات في تطبيق واحد.

> **حالة الإصدار:** قدرات v1 منفذة في المستودع وقابلة للتحقق بالاختبارات
> الآلية. هذا لا يُعد تصريحاً للنشر الإنتاجي؛ يجب إغلاق بوابات البيئة والـpilot
> في [قائمة جاهزية الإصدار](docs/RELEASE_READINESS.md) أولاً.

## الوظائف المنفذة

- لوحة متابعة من بيانات العمل الفعلية، بمؤشرات ورسوم وعبء الفريق ومخاطر ومشكلات
  قابلة للانتقال إلى تفاصيلها. تعتمد اللوحة وقائمة المشاريع على مصدر حساب موحد
  للتقدم والصحة والمرحلة التالية.
- جدول أسبوعي من الأحد إلى السبت مع اختيار الأسبوع، وصف لكل مشروع، وأشرطة مهام
  تمتد من تاريخ البداية إلى تاريخ النهاية، مع قص بصري آمن عند حدود الأسبوع.
- مشاريع يمكن إنشاؤها بلا مهام، ثم إضافة أول مهمة من سياق المشروع، مع قائمة
  وكانبان وفرز وترقيم صفحات وتغيير حالة بالسحب أو بالكيبورد.
- مهام ببداية ونهاية إلزاميتين، ومسؤول اختياري، ووقت إسناد مستقل، وسجل كامل
  لإعادة الإسناد، وربط بالمتطلبات داخل المشروع نفسه.
- متطلبات وكراسة متطلبات بإصدارات، ومراحل، واجتماعات ومحاضر ومرفقات، ومخاطر
  ومشكلات. تحمي `lock_version` السجلات القابلة للتحرير من الكتابة فوق تعديل أحدث.
- مراحل موزونة ومعالم تسليم إلزامية، وWizard ذري للمشاريع التي بدأت قبل النظام،
  وشجرة تصنيف وعلاقات للمتطلبات. يمكن تحليل PDF وDOCX محليًا عبر Ollama وOCR
  مع مراجعة بشرية كاملة؛ راجع
  [دليل التحليل المحلي](docs/LOCAL_REQUIREMENTS_ANALYSIS_AR.md).
- ملفات خاصة يمكن ربطها بالمشروع أو بمهمة أو متطلب نشطين داخله. يتحقق الخادم
  من الهدف قبل التخزين وداخل المعاملة، ولا يسمح بالتنزيل إلا بعد نجاح فحص
  البرمجيات الخبيثة. يحفظ الأرشيف التاريخ، وتزيل مهمة الاحتفاظ المجدولة الملفات
  اليتيمة فقط بعد مهلة وإعادة تحقق وحجر قابل للتراجع.
- قوالب فواتير بهوية CloudTech، مع محرر بنود ومعاينة A4 وحسابات المستند
  (الخصم والضريبة والإجمالي) وتصدير PDF مصرح ومدقق. الوحدة ليست نظاماً
  محاسبياً ولا تتعقب الأرصدة أو التحصيل أو حالات الدفع.
- استيراد ذري وتصدير فعلي لـExcel وCSV، وملخص PDF للمشروع، ونسخ `.pdesk`
  مشفرة تضم لقطة SQLite والملفات مع تحقق من الاكتمال واستعادة محمية بسياج كتابة
  ونسخة أمان قبل الاستعادة.
- مصادقة داخلية و2FA وPasskeys وصلاحيات، مع تدقيق أحداث الدخول والعوامل الأمنية
  دون تخزين الأسرار، وسجل نشاط للعمليات، وحراسة موحدة للمسودات غير المحفوظة.
- إعدادات النظام والتنبيهات الدائمة والتقويم وحالات سير العمل وهوية CloudTech.
- مبدل لغة متاح للزائر والمستخدم المسجل؛ يحفظ الاختيار في Cookie مشفرة لمدة
  سنة، ويضبط `lang` و`dir` وتنسيق الأرقام والتواريخ بحسب العربية أو الإنجليزية.
  لا يترجم التبديل بيانات المستخدم المخزنة، ولا يغير لغة مخرجات PDF العربية
  الحالية.

## المتطلبات

- PHP 8.3 أو أحدث مع الامتدادات المذكورة في
  [دليل البيئة](docs/ENVIRONMENT.md).
- Composer 2.x.
- Node.js 22.12 أو أحدث.
- pnpm 11.16.0.
- للتحليل المحلي الاختياري: Ollama مع Qwen3 وPoppler وTesseract `ara+eng`؛ لا
  يحتاج إلى مفتاح API أو اشتراك سحابي.
- ملف نشر v1 المعتمد: خادم Linux واحد وSQLite بوضع WAL وتخزين ملفات خاص.
  التوسع الأفقي أو الانتقال إلى PostgreSQL يتطلبان محول نسخ واستعادة واختبارات
  تشغيل مستقلة قبل اعتمادهما.

## إعداد محلي سريع

```powershell
composer setup
```

ينشئ الأمر ملف البيئة والمفتاح وقاعدة SQLite عند الحاجة، ويشغّل migrations،
ويثبت حالات سير العمل، ثم يطلب بيانات أول مدير داخلي بصورة تفاعلية، ويثبت ويبني
الواجهة. إذا كان مدير نشط موجوداً فلن ينشئ حساباً مكرراً.

بعدها شغّل بيئة التطوير:

```powershell
composer run dev
```

أو شغّل الخادم والواجهة كل واحد في نافذة مستقلة:

```powershell
php artisan serve
pnpm run dev
```

### تشغيل يومي بأيقونة على ويندوز

بعد إكمال `composer setup` مرة واحدة، أنشئ اختصار سطح المكتب بالأمر التالي:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\windows\Install-ProjectDeskShortcut.ps1
```

اختصار **Project Desk** يشغّل خادم Laravel والـscheduler والـqueue في الخلفية
إذا لم تكن تعمل، ثم يفتح `http://127.0.0.1:8000` في المتصفح الافتراضي. لا
يحتاج الاستخدام اليومي إلى تشغيل Vite لأن الاختصار يستخدم الواجهة المبنية في
`public/build`. لإيقاف عمليات Project Desk الخلفية يدويًا:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\windows\Stop-ProjectDesk.ps1
```

### بيانات العرض المحلية

لإعادة قاعدة التطوير إلى بيانات العرض التجريبية فقط:

```powershell
php artisan migrate:fresh --seed
```

ينشئ `DemoDataSeeder` في بيئة `local/testing` حسابات تنتهي بالنطاق
`@projectdesk.local` بكلمة المرور التجريبية `password`. لا تستخدم بيانات العرض
أو كلمة المرور هذه في الإنتاج.

## التحقق من مرشح الإصدار

```powershell
composer validate --strict --no-check-publish
composer audit --locked --no-interaction
composer test
pnpm run format:check
pnpm run lint:check
pnpm run types:check
pnpm run build
```

يشغّل `composer test` فحص تنسيق PHP والتحليل الساكن ثم اختبارات Laravel بحد
ذاكرة مناسب للمجموعة الكاملة. لا تسجل أرقام النجاح في الوثائق إلا من تشغيل كامل
على commit مرشح محدد.

رحلات المتصفح موجودة في `tests/Browser` وتشمل الرحلة الحرجة، وقوالب الفواتير، والملفات
ومركز البيانات، والحوكمة، والتنبيهات، والوصولية/الاستجابة، وتبديل العربية/
الإنجليزية واتجاهي RTL/LTR، وتراجعات المهام، وحراسة النماذج غير المحفوظة. تتطلب
Chrome وخادماً محلياً مهيأ يعمل على
`http://127.0.0.1:8000` افتراضياً:

```powershell
pnpm run browser:check
```

احتفظ بنتيجة الأوامر وبيئة التشغيل وSHA الخاص بالـcommit وفق
[قائمة جاهزية الإصدار](docs/RELEASE_READINESS.md).

## متطلبات التشغيل الإنتاجي

يجب استدعاء Laravel scheduler مرة كل دقيقة وتشغيل queue worker تحت Supervisor
أو systemd. من الـscheduler تعمل مزامنة التنبيهات والنسخ التلقائي وتنظيف الملفات
اليتيمة وفق السياسة. يمكن التحقق اليدوي دون حذف ملفات في أمر الاحتفاظ:

```powershell
php artisan schedule:run
php artisan project-desk:sync-notifications
php artisan project-desk:automatic-backup --force
php artisan project-desk:prune-orphaned-files --dry-run
```

قبل الإنتاج يجب أيضاً تهيئة ماسح فعلي يعمل بسياسة fail-closed، ونسخ حزم
`.pdesk` إلى وجهة خارج المضيف، وإجراء restore drill معزول، وتفعيل TLS وملفات
الجلسات الآمنة، وتنفيذ تدقيق قارئ شاشة/تكبير 200% وقياس INP وتجربة pilot.
التفاصيل ومعايير الإثبات موجودة في
[قائمة جاهزية الإصدار](docs/RELEASE_READINESS.md).
